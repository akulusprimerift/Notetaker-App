# Phase 6.9.3 — macOS integration

Active phase: **6.9.3**, requested by the user; source preparation on Windows, 2026-09-30. Earlier 6.9.1 containment, 6.9.2 native runtime and Windows release/human-quality gaps remain open. This increment does not qualify an installed Mac app.

## Implemented behavior

- Mac uses standard native window controls and application menus. Command-comma opens workspace settings, Command-Q enters guarded Quit, Command-W closes/hides the workspace; Edit roles provide native text shortcuts. Zoom/fullscreen and Show Workspace are available. Reload is intentionally absent from menus because it can interrupt capture and edits. Windows retains its integrated titlebar and existing close choices.
- Closing the main Mac window hides the same renderer, retaining recording and drafts. Dock activation and a second launch restore that window, including from minimized state. Quit defaults to keeping the app open and explicitly advises stopping capture and waiting for confirmed saves. Confirmed Quit uses the existing owned-service cleanup; journaled evidence remains recoverable. Quit is not a promise to save RAM-only audio or wait for all uploads. Setup is a separate window.
- The microphone handler admits only audio from the loopback workspace. Mac requests OS consent when undetermined; denied/restricted status offers a fixed Microphone Settings destination and explains restart/admin recovery. Consent is rechecked against the requesting page after asynchronous dialogs. A Capture panel Settings button supports recovery even when Chromium rejects access before the permission handler. Packaging includes the microphone purpose text. No microphone permission is requested during startup.
- Main-process suspend/resume events cross a narrowly scoped preload subscription. The recorder stops on either event if capture remains active, flushes available samples through its existing worker/journal, and records an unknown-extent `sleep_or_suspension` gap. An in-flight start is cancelled at admission boundaries. Wake never automatically restarts capture. The saved status keeps interruption language after uploads succeed. Existing AudioContext and stalled-sample checks remain additional safeguards.
- Existing Electron safeStorage protects library credentials and API-key connection files; on Mac its key is backed by Keychain. The official account helper already requires `cli_auth_credentials_store="keyring"`, with no plaintext fallback. This increment gives new credential files owner-only POSIX modes and platform-neutral recovery text. Unavailable encryption/decryption preserves the existing encrypted file. It neither imports another app's tokens nor migrates Windows credentials to Mac.
- Setup labels and library paths no longer assume Windows. No database migration, API/domain change, source-history mutation or student-data change is required.

Electron references: [microphone permission APIs](https://www.electronjs.org/docs/latest/api/system-preferences), [power events](https://www.electronjs.org/docs/latest/api/power-monitor), and [protected storage and Mac signing caveat](https://www.electronjs.org/docs/latest/api/safe-storage). Consistent signing is still needed to qualify Keychain behavior across upgrades; this development build does not establish it.

## Executed evidence — Windows

- Desktop contracts: **39 passed**, including permission denial/restriction/navigation, native menu actions, close/Dock/guarded Quit, encrypted-file preservation on storage failure and existing runtime/provider/startup tests. Mac host behavior is simulated, not native OS evidence.
- JavaScript contracts: **62 passed**, including interruption flush/seal, retained gap/sample count, duplicate power events and cancellation while a stream request is pending.
- Actual Chromium generated-tone capture passed with real AudioWorklet, packaging worker and IndexedDB: suspend while the simulated API is offline → retained journal bytes and explicit gap → resume without capture restart → retry with SHA-256 matching → seal without inventing samples → close/reopen journal with gap and saved state retained. The run retained **97,536 samples**. This is a simulated service test, not PostgreSQL/object-store durability evidence. Command: `bun tests/desktop/power-capture-smoke.cjs` (Windows Playwright path).
- Actual isolated Windows Electron first-launch setup, sandbox/context isolation, preload subscription/unsubscribe filtering and clean Quit passed without opening a library. Profile: `.local/foundation-smoke-00b9114a-d658-44d3-b9dc-72ac949a4232`. Command: `bun tests/desktop/foundation-smoke.cjs`.

- Initial runs caught a local edit encoding error and an outdated main-process test mock; both were repaired and the affected suites rerun. No unresolved test failure is being carried as a pass.

No real microphone, OS sleep, native Mac executable, Keychain interaction, live provider, model download, student library, installer replacement, installation or push was used. Full backend and packaged runtime suites were not rerun; installed artifacts remain unchanged.
