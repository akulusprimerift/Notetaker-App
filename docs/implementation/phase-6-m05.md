## Student behavior

- Keep the note detail and layout presets as starting points, or enter separate descriptions of up to 2,000 characters each. A nonblank description overrides its corresponding preset in the model prompt. General writing preferences remain separate. The wider desktop controls and stacked narrow-window controls retain the descriptions through connection interruptions. Apply saves an immutable settings version; generated revisions retain the exact profile. Text is rendered through the existing safe heading/passage structure, not arbitrary HTML or a new document-layout engine.
- Verified, contiguous audio becomes eligible for transcription during recording. The live connection panel shows seconds of **saved audio awaiting transcription**, separately from recording/upload confirmation. Notes display generation state and whether newer transcript passages are pending. Backlog seconds describe unprocessed audio duration, not an estimated completion time.
- The transcript snapshot is provisional while recording, recovery, or processing is incomplete. Completed context-backed passages have stable source identities. Stopping and completing the remaining windows produces a stable snapshot without duplicating earlier live passages. This is incremental window recognition, not token-by-token provisional word rendering.
- Notes arrive during recording once a model is selected. A new revision waits behind **Show updated notes** when a revision is already displayed, preserving the reading copy, selected text and export target. Transcript appends retain DOM keys; revisions to existing passages wait behind **Show transcript revisions**. Reconnecting does not remount the workspace, clear a correction, move focus or reset scroll. The browser test explicitly closes the WebSocket and takes the browser offline.

## Architecture and failure behavior

**Database migration 0006** adds custom prompt fields, a live-window flag and persisted transcript snapshot stability. Existing settings receive empty descriptions and existing snapshots remain stable. No data is removed or copied. The existing Windows startup migration command upgrades to the new head; rebuild the API and web services to install the WebSocket runtime dependency.

**Speech windows:** retain the M03 24-second core and two-second context policy. Live inference waits for a full right context (first eligibility at 26 saved seconds); final tails run after seal. Saved-only pause-aware planning remains available. Each input is bounded, verified and sample-addressed. Appended chunks and seal do not invalidate existing live cores. A newly declared gap through a window's context does invalidate it, fencing stale worker publication. Stop/recovery publishes a transcript snapshot in the same transaction, preventing a note result from using newly invalidated passages before reconciliation runs. The roadmap's shorter six-second/12-second trigger settings remain performance candidates; this increment preserves the established speech window size rather than claiming an unmeasured low-latency default.

**Notes:** one active request uses immutable transcript/settings/model inputs. Unclaimed requests are superseded by the newest snapshot; the database snapshot acts as the pending watermark during an active request. Append-only changes permit the running request to finish; it is visibly stale until the coalesced follow-up completes. Corrections, removed source membership, settings/model changes and lifecycle/audio epochs still fence publication. Invalid output retains the last valid revision and export. Model failures leave audio uploads and transcript sources available. Automatic retry limits remain those of M04; exhausted note retries require the existing Retry notes action.

**Shared resource budget:** speech and note claims serialize on the owner row and admit one active inference job across both workers. Capture never acquires this budget. A dedicated PostgreSQL connection holds a session advisory lock throughout provider execution, so an expired job lease cannot permit concurrent model calls while the previous process still runs. Process/connection exit releases that lock; publication remains attempt-token fenced. SQLite preview uses an in-process execution lock and is not the supported multiprocess speech deployment. This bounds active inference concurrency, not resident model RAM/VRAM; real memory and scheduling performance remain G03 qualification work.

**Replay:** `/lectures/{id}/updates?after=N` returns versioned invalidation events from PostgreSQL's durable lecture update log in ordered pages of at most 100, independently of Kafka. Missing/pruned, malformed and future cursors request an authoritative snapshot. Each page/heartbeat rechecks the session and lecture authority. Snapshot data and its cursor are read under the lecture lock; the client applies them together, ignores old invalidations and reconnects with backoff. Heartbeats refresh processing state even when no content revision changes. The four-second component polling fallback remains available. The event log is not automatically pruned in this increment; recovery tests simulate missing history. The pinned `websockets` dependency enables Uvicorn upgrades through the existing Next.js rewrite.
