# Phase 6.6 / M06 — Protected editing and regeneration

Implemented 2026-09-08, together with the user's requested M05 improvements. The scope is prompt-driven note preferences, continuous segmented transcription, visible generation, durable student drafts and safe regeneration resolution. Finalization/deletion remains M07; Windows packaging remains M08. Synthetic engineering checks do not establish real-lecture quality or hardware performance.

## Live notes and custom preferences

The redundant Note detail and Note layout dropdowns are removed. Students describe their desired detail, layout and writing style directly. Applying preferences records an immutable settings snapshot. Existing historical preset values remain readable; new UI saves use detailed/topic defaults when custom descriptions are blank. Regenerate notes explicitly starts a new preference/request version, even when the descriptions are unchanged.

Live speech uses six-second cores with two seconds of context on either side, where available. The first core becomes eligible after eight seconds of contiguous verified audio; actual display latency additionally includes upload, queueing and model time. The existing two-second capture chunks are unchanged. Saved-audio planning still supports the established longer pause-aware windows. Gaps invalidate crossing windows and late sealed tails are retained. Equally due speech jobs are ordered by source position rather than random UUID.

The speech service loads its already-provisioned local model at startup so the first recording does not initiate model loading. Missing models remain an explicit recoverable condition; startup never downloads weights.

During recording, note generation waits for 24 seconds of recognized audio windows containing new transcript passages, or 100 new words. Short final tails flush after recording stops; corrections and preference changes bypass this initial accumulation rule. This is a context threshold, not a guarantee of an educationally complete topic. Coalescing retains the newest transcript while an append-only generation is running.

Speech and notes each have one inference slot, protected by separate PostgreSQL advisory locks and per-kind claims. They can run concurrently; duplicate calls of the same kind remain fenced. This intentionally replaces M05's single shared inference slot so slow note writing cannot stop transcription. Actual combined RAM/VRAM use and sustained real-time factor remain qualification work.

The note worker splits new input into batches of at most 16 sources and 8,000 source-text bytes, retaining up to two preceding passages (2,500 characters) as orientation. Unchanged source-backed notes are reused under unchanged preferences. Corrections rebuild the affected snapshot through bounded batches; changed model/preferences regenerate it. A single source exceeding the model's safe capacity still fails visibly rather than being truncated. Individual provider responses keep the original strict schema; the assembled lecture has a separate bounded aggregate validator (10,000 blocks/issues and 20,000 source entries). Batch metadata records source membership and provider provenance. This is chronological contextual batching, not a qualified semantic topic detector or human-reviewed cross-topic synthesis.

Ollama uses NDJSON streaming. The adapter extracts partial heading/passage strings without displaying JSON bookkeeping. The worker persists a bounded preview under its current attempt token. An authenticated server-sent event connection forwards current text and recovers its latest preview after reconnect. Preview text is explicitly unvalidated and never becomes the export target. Only a complete, source-validated revision is saved; failed, expired or superseded attempts cannot replace valid notes. Previously selected reading copies remain available while live draft text appears separately.

Browser verification caught Next.js gzip buffering the small event-stream writes. Compression is disabled for this loopback app; direct API and frontend-proxy probes now both receive the first frame immediately. The preview follows new text within its own scroll area until the student scrolls upward; it does not move the main reading copy.

## Editing and resolution

Migration **0007** adds a recoverable preview on note requests and immutable `note_edits` history. It is additive and preserves previous audio, transcript, generated notes and settings. No destructive downgrade is provided.

Students can edit headings/passages and add their own text. IndexedDB stores local drafts after edits, including the base revision, expected version and stable save/retry key. Reloading offers draft recovery. Draft-storage failures are shown explicitly; export always uses a saved revision. Drafts are separate records so independent tabs do not overwrite one shared storage key.

Saving uses CSRF, lecture ownership, idempotency and a lecture lock with an expected student version and base ID. A newer saved copy rejects a stale save while retaining the draft. The user can compare and transfer edited passages onto the latest copy; untouched passages keep the newer wording, and unmatched edits become student additions rather than disappearing.

Automatic generations remain immutable machine revisions. Once a student revision exists, later output is a **proposal** and cannot change the selected student copy. Comparison shows current and suggested sections. Keep records the choice, merge appends explicitly checked sections, and replace selects the full proposal. Undo restores an earlier generated or student copy as another immutable student revision. Old exports remain reproducible.

Resolution checks the current proposal, settings/model version, source membership and lifecycle/audio epochs. Source corrections invalidate outdated proposals while original evidence remains available in protected student notes. Merged revisions retain provenance from their contributing generated revisions. Student changes are labeled as student text; original citations are retained for review without claiming that they substantiate newly added wording. Markdown exports preserve whitespace and escape arbitrary text, including student additions.
